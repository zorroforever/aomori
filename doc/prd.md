# Aomori 总体 PRD

## 1. 产品定位

Aomori 是面向 MUD/文字冒险世界的确定性自治世界引擎。Rust 负责账号、权限、资产、实体、事务和状态一致性；Lua 负责可迭代的世界规则、命令、任务和 NPC 行为。

## 2. 目标用户

- 世界规则和剧情设计者
- MUD 客户端开发者
- 希望验证链上游戏状态机的工程团队

## 3. 核心原则

1. 世界事实由 Rust 状态机掌握，Lua 不能绕过权限修改任意状态。
2. 查询和命令分离：查询不改变状态，命令在事务中执行。
3. 相同初始状态和输入必须产生相同状态根。
4. 合约版本发布后不可变，升级采用新版本和迁移。
5. RPC 面向结构化 action，不要求客户端拼接 Lua 字符串。

## 4. 目标架构

```text
客户端 -> HTTP/WebSocket RPC -> Rust Runtime -> Lua Host API
                                      |
                           World State + State Root
```

未来再加入 RocksDB、区块、P2P、BFT 共识和索引服务。

## 5. 主要领域对象

- Account：账号、公钥、nonce、余额
- Entity：通用实体
- Actor：可操作角色，具有当前位置
- Zone：区域及出口图
- Contract：Lua 源码、哈希、版本和发布状态
- Transaction：签名操作和执行收据

## 6. 非目标

当前阶段不实现多节点共识、经济通胀、生产级钱包、复杂索引、兼容 Taiyi 二进制协议。

## 7. 成功标准

能够在本地启动节点，部署 Lua 合约，创建两个相连区域和一个角色，执行 `look`、`go`，并在脚本失败时保持状态根不变。
